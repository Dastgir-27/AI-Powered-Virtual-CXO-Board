📌1. Project Overview

The AI-Powered Virtual CXO Board is a web application that simulates an AI boardroom of four distinct C-suite executives — CFO, CMO, COO, and CSO — that a CEO can converse with to explore business strategy, analyse financial performance, and pressure-test decisions.

Instead of a single generic chatbot, each persona has a unique personality, set of priorities, and communication style. The system generates two rounds of responses per CEO question: an initial perspective round, followed by a live debate round where executives push back on each other by name.

Primary Goal

Create a "boardroom in a box" — distinct AI executive personas that disagree constructively, the way a real leadership team would.

Target User

A CEO or founder who wants to stress-test strategic decisions with multiple lenses before acting.

Scope

Working prototype with multi-agent orchestration, session management, and P&L data upload for contextual grounding.

Key Constraint

Free-tier Gemini API — engineered to maximise quality while minimising API calls and handling quota limits gracefully.

👥3. Executive Personas

Each persona is implemented as a detailed system prompt that defines their background, priorities, communication style, and inter-personal dynamics with other executives.

AC
Alex Chen
Chief Financial Officer (CFO)
  • Protects margins, EBITDA, and cash flow above all
  • Demands clear ROI within 18 months before any spend
  • Always references specific numbers from P&L data
  • Frequently clashes with CMO on brand spend
  • Style: direct, numbers-first, blunt
PS
Priya Sharma
Chief Marketing Officer (CMO)
  • Defends brand equity as a long-term strategic asset
  • Believes market share won during downturns is durable
  • Pushes back hard on blanket cost cuts from CFO
  • Aligns with CSO on positioning and competitive strategy
  • Style: energetic, customer-centric, strategic
MW
Marcus Williams
Chief Operating Officer (COO)
  • Views most financial problems as operational problems
  • Identifies specific levers: headcount, vendors, automation
  • Acts as pragmatic mediator between CFO and CMO
  • Always offers concrete next steps and milestones
  • Style: calm, methodical, action-oriented
JP
Jordan Park
Chief Strategy Officer (CSO)
  • Thinks in 3–5 year competitive positioning arcs
  • Brings external context: competitor moves, industry trends
  • Challenges short-term optimisation that damages the moat
  • Ex-McKinsey background, frameworks-driven thinking
  • Style: thoughtful, big-picture, occasionally provocative
💡
Persona Design Philosophy: The executives are designed to have genuine, grounded disagreements — CFO vs. CMO (cost vs. growth), CFO vs. CSO (short-term vs. long-term), COO as pragmatic bridge. This creates authentic boardroom dynamics, not just parallel summaries.

🔄4. Interaction Workflow

The entire boardroom discussion for each CEO message is powered by exactly 2 Gemini API calls — one per round. Each call returns a structured JSON array with all 4 executive responses simultaneously.

1

CEO Submits a Question

User types a business question in the chat interface. The message is immediately rendered in the chat timeline (optimistic UI) and sent to the backend via POST /api/session/:id/message.

2

Session Context Built

The server loads the session history (up to 10 recent messages) and any uploaded P&L data. This context is injected into the prompt so the board can reference real company numbers.

3

Round 1 — Initial Perspectives (1 API call)

A single Gemini API call with all 4 persona definitions and the CEO question. The model is instructed to return a JSON array with all four executives' initial responses in one shot using structured JSON output mode (responseMimeType: "application/json").

4

Round 1 Responses Saved

The 4 Round 1 messages are parsed, assigned UUIDs, timestamped, and persisted to the session JSON file on disk. Session is saved as a checkpoint — even if Round 2 fails, Round 1 is safe.

5

Round 2 — Debate (1 API call)

A second Gemini API call passes the Round 1 responses back into the prompt. Each executive is instructed to react to their colleagues by name — agreeing where reasonable and pushing back on disagreements. Output is again a JSON array.

6

All Messages Returned to Frontend

The API returns all new messages (CEO + 4 Round 1 + 4 Round 2 = 9 messages) in one response. The frontend re-renders the full session with round dividers automatically.

Request → Response Lifecycle (simplified)
POST /api/session/:id/message  { content: "Our Q3 margins dropped 4 points…" }
    │
    ├─ Save CEO message to session
    │
    ├─ [Round 1] Gemini API call → returns JSON array of 4 initial responses
    │   ├─ CFO: "A 400 basis point drop directly impairs free cash flow…"
    │   ├─ CMO: "A 4-point compression is a call to optimize, not retreat…"
    │   ├─ COO: "The drag isn't ideological — it's operational friction…"
    │   └─ CSO: "This is a strategic capital reallocation moment…"
    │
    ├─ Save Round 1 to session file

    │   └─ CSO: "Alex, your freeze logic is sound short-term, but…"
    │

    │

🛡️6. Error Handling & Resilience

Model Cascade Fallback

The server maintains a prioritised list of Gemini models. If any model exhausts its daily quota, the system automatically switches to the next without surfacing an error to the user.

🥇 gemini-flash-latest
Primary (gemini-3.6-flash)
→
🥈 gemini-3.5-flash
Fallback #1
→
🥉 gemini-3.5-flash-lite
Fallback #2

Error Type Detection

Error TypeHTTP CodeAction Taken
Daily Quota Exhausted 429 PerDay Immediately switch to next model in cascade (no wait)
Per-minute Rate Limit 429 PerMin Wait with exponential backoff (8s → 16s → 32s) and retry same model
High Demand / Overloaded 503 Wait and retry same model (transient spike)
Model Deprecated 404 Caught at startup; model cascade prevents cascading failures

Frontend Resilience

✅
Optimistic UI: CEO messages are rendered in the chat immediately on send, before the API call completes. This prevents the UI from appearing frozen during the 5-15 second AI processing window.
✅
Session Checkpointing: Round 1 responses are saved to disk before Round 2 starts. If Round 2 fails, the session retains Round 1 and the user can refresh to see partial results.

🚀9. Deployment

Platform

Render.com — Free tier Node.js web service. Auto-deploys on every GitHub push to main branch.

Environment Variables

Only one required: GEMINI_API_KEY — set securely in Render's dashboard.

⚠️
Free Tier Note: Render spins down the server after 15 minutes of inactivity. The first request after inactivity may take 15-30 seconds to cold-start. Session files are lost on server redeploy (ephemeral disk). For persistent sessions in production, a database like PostgreSQL or MongoDB is recommended.

⚙️10. Key Design Decisions

DecisionChoice MadeRationale
Response Format Structured JSON mode Guarantees parseable output for all 4 personas in one call; prevents markdown leakage
API Calls per Message 2 (batch per round) Reduced from 8 (one per persona per round) to stay well within free-tier daily limits
Session Storage JSON files on disk Zero-dependency persistence; trivial to inspect/debug; no DB setup required for prototype
Error Strategy Model cascade + backoff Distinguishes daily quotas (switch model) vs. transient spikes (wait & retry same model)
Frontend Framework Vanilla JS SPA No build step; instant deploy; keeps focus on core AI interaction, not framework boilerplate
Auth None Prototype scope — auth intentionally excluded to focus on multi-agent reasoning quality
